## 1. ملخص منصة زامو

**زامو** منصة سعودية ذكية لاكتشاف الأطباء والخدمات الطبية وحجز المواعيد، تربط المرضى بالمستشفيات والمجمعات والعيادات، وتستخدم وكيل ذكاء اصطناعي لفهم احتياج المريض، وترشيح الخيارات المناسبة، وإتمام الحجز، ثم متابعة حالة الزيارة وحساب الإيرادات والعمولات. `[S1]`

### 1.1 القرارات المعتمدة (من ملخص القرارات في `[S2]`)

**النطاق الأول:**
- السوق: المملكة العربية السعودية.
- مدينة الإطلاق: الرياض — جميع الأحياء.
- التخصصات: الأسنان، الجلدية، التجميل.
- الهدف التجاري: **6 عيادات خلال أول 6 أشهر**.

**نموذج العمل:**
- زامو **وسيط حجز وليست مقدم رعاية صحية**.
- الدفع **داخل المنشأة** (لا يوجد دفع إلكتروني في النسخة الأولى).
- عمولة افتراضية **10% قابلة للتعديل**.
- العمولة تُحتسب على **الخدمة المنفذة والمحصل مبلغها** (وليس على مجرد طلب حجز).
- **فاتورة عمولة شهرية**.

**آلية الحجز:**
- الوكيل الذكي هو **القناة الأساسية** (والبحث اليدوي مسار بديل).
- الحجز **يحتاج تأكيد الاستقبال**.
- الإلغاء وإعادة الجدولة متاحان.
- الخدمات **حضورية فقط**.
- المريض يختار **خدمة محددة**.

**هيكل المنشآت:**
- المنشأة الواحدة لها **عدة فروع**.
- الطبيب **يتبع منشأة واحدة** وقد يعمل في فروعها.
- إدارة المنشأة **تعتمد الأسعار والعروض**.
- المنصة تعرض **قبول التأمين دون ضمان التغطية**.

### 1.2 المبدأ الحاكم `[S2]`

> **لا يقدّم وكيل زامو تشخيصًا أو علاجًا. دوره إداري: فهم الخدمة المطلوبة، عرض الخيارات، الحجز، المتابعة والتذكير.**

### 1.3 تعريف النجاح الأول `[S2]`

> القدرة على تتبع العميل من الإعلان إلى طلب الحجز، ثم تأكيده وحضوره وتنفيذ الخدمة وتحصيل قيمتها وإصدار عمولة شهرية قابلة للمراجعة.

هذه هي **رحلة القيمة الأساسية (Core Value Chain)** التي يجب أن تعبرها المنصة بنجاح:

```
الإعلان ← مصدر العميل ← طلب الحجز ← تأكيد العيادة ← الحضور
   ← تنفيذ الخدمة ← تحصيل القيمة ← احتساب العمولة ← الفاتورة الشهرية
```

## 4. الأدوار والصلاحيات

### 4.1 جدول الصلاحيات المعتمد `[S2]`

| نوع المستخدم | أهم الصلاحيات | قيود ضرورية |
|---|---|---|
| **مدير زامو** | إدارة جميع المنشآت، العمولات، الحملات، التوثيق والتقارير. | تسجيل **كل تعديل مالي** في سجل التدقيق. |
| **مدير المنشأة** | الفروع، المستخدمون، الأطباء، الأسعار، العروض، اعتماد المبالغ. | **لا يرى بيانات منشآت أخرى.** |
| **مدير الفرع** | جدول الفرع، فريق الاستقبال، الأطباء والخدمات التابعة للفرع. | صلاحياته **داخل الفرع المحدد**؛ لا يغير العمولة ولا يعتمد الأسعار الأساسية. |
| **موظف الاستقبال** | تأكيد ورفض وإعادة جدولة، تسجيل الحضور والخدمة والتحصيل. | **لا يعتمد العرض أو القيمة النهائية منفردًا.** |
| **الطبيب** | جدوله، تفاصيل الموعد، اقتراح تعديل الخدمة أو السعر. | لا يصل إلى بيانات داخلية للمنشأة / لا يعدل الحجوزات الطبية (انظر التنبيه أدناه). |
| **المحاسب** | كشف الخدمات، مبالغ التحصيل، العمولات والفواتير. | (لم تُذكر قيود صريحة — انظر OQ-014) |
| **المريض** | الطلب، الإلغاء، إعادة الجدولة، متابعة الحالة والاعتراض. | (نطاقه بياناته فقط) |

> ⚠️ **ملاحظة تعارض:** في `[S2]` تداخلت خلايا جدول الصلاحيات عند استخراج نص الـPDF، فظهرت عبارتا «لا يعدل الحجوزات الطبية» و«لا يصل إلى بيانات داخلية للمنشأة» بترتيب ملتبس بين صفّي **الطبيب** و**موظف الاستقبال**.
> القراءة المنطقية المرجّحة: **موظف الاستقبال** لا يعدل الحجوزات الطبية، و**الطبيب** لا يصل إلى بيانات المنشأة الداخلية (المالية).
> ← مسجّل كـ **OQ-001** ولا يُبنى عليه كود قبل الاعتماد.

### 4.2 قواعد صلاحيات إضافية مستخرجة

- الطبيب: «يسجل الخدمة **عند منحه الصلاحية**» `[S1]` ← تسجيل الخدمة صلاحية اختيارية قابلة للتفويض للطبيب، وليست افتراضية.
- الطبيب: «يعرض جدوله المؤكد ضمن **فروع منشأته فقط**» و«يستعرض اسم المريض والخدمة والوقت **دون صلاحيات مالية كاملة**» `[S2]`.
- إدارة المنشأة هي من **تعتمد التعديل النهائي** على السعر أو الخدمة `[S2]`.
- «لا تغير إدارة زامو حجزًا مؤكدًا **دون تسجيل السبب وإبلاغ الأطراف**» `[S1]`.
- المنشأة: «لا يرى بيانات منشآت أخرى» ← **عزل بيانات إلزامي على مستوى المنشأة (Tenant Isolation)**.

### 4.3 آلية إنشاء الحسابات `[S2]`

| الكيان | الآلية |
|---|---|
| **المنشأة** | طلب انضمام يتضمن السجل والترخيص وبيانات المفوض والفروع. **تراجع زامو الطلب قبل التفعيل.** |
| **المستخدمون الداخليون** | ينشئ مدير المنشأة دعوة مرتبطة برقم الجوال والبريد والدور والفرع، مع رمز تحقق. |
| **الطبيب** | يُضاف بواسطة المنشأة مع رقم الترخيص والتخصص والخدمات والفروع والجدول. |
| **المريض** | حساب خفيف برقم الجوال ورمز تحقق. **يمكن بدء المحادثة قبل التسجيل وإتمام التحقق عند الحجز.** |

> قاعدة مهمة: **الوكيل الذكي يعمل للزائر غير المسجّل**، والتحقق (OTP) يُطلب عند لحظة الحجز فقط.

> تستهدف العيادة تأكيد الطلب خلال **15–30 دقيقة** أثناء ساعات العمل. تبقى **24 ساعة** حدًا أقصى فقط، وبعد التأخير **يعاود الوكيل التواصل ويعرض بدائل**.

### 6.2 رحلة موظف الاستقبال `[S1+S2]`

```
1. يستلم إشعار طلب حجز جديد مع مصدر العميل.
2. يراجع توفر الطبيب والفرع والخدمة (التقويم).
3. يؤكد الطلب / يقترح بديلًا / يرفضه مع سبب مسجل.
4. عند الموعد يحدد: حضر / لم يحضر / ألغى.
5. إذا حضر: يحدد هل نُفذت الخدمة، وما الخدمة الفعلية.
6. يدخل المبلغ النهائي المحصل وطريقة الدفع.
7. ترسل العملية لاعتماد إدارة المنشأة وتدخل في كشف العمولة.
```

**قاعدة حرجة:** موظف الاستقبال **يُدخل** القيمة ولا **يعتمدها**. الاعتماد لإدارة المنشأة `[S1+S2]`.

### 6.3 رحلة الطبيب `[S1+S2]`

```
1. يسجل الدخول.
2. يعرض جدوله المؤكد ضمن فروع منشأته فقط.
3. يستعرض اسم المريض والخدمة والوقت دون صلاحيات مالية كاملة.
4. يحدد أوقات توفره والإجازات.
5. يراجع الخدمات ومددها.
6. يقترح تعديل خدمة أو سعر (اقتراح فقط).
7. يسجل الخدمة عند منحه الصلاحية.
8. يرسل القيمة للإدارة ← تعتمد إدارة المنشأة التعديل النهائي.
```

### 6.4 رحلة مدير المنشأة `[S1+S2]`

```
1. يدير الفروع والمستخدمين.
2. يضيف الأطباء ويرفع التراخيص.
3. يعتمد الأطباء والخدمات.
4. يحدد الخدمات والمدد والأسعار.
5. يعتمد الأسعار والعروض.
6. يراقب الحجوزات.
7. يعتمد القيم المحصلة (القيمة النهائية).
8. يراجع العمولة.
9. يراجع الفاتورة الشهرية ويعتمد كشف العمولة.
10. يقدم اعتراضًا عند الحاجة.
11. يسجل السداد.
```

### 6.5 رحلة إدارة زامو `[S1]`

```
1. تعتمد العيادة والتراخيص.
2. تضبط العمولة.
3. تربط الحملة بالعيادة والخدمة.
4. تراقب الحجوزات.
5. تتابع مستوى الاستجابة (زمن التأكيد).
6. تعالج الحجوزات المتعثرة.
7. تراجع الخدمات المحصلة.
8. تصدر الفاتورة الشهرية.
9. تتابع السداد.
10. تقيس هامش المساهمة.
```

### 6.6 رحلة الحجز — خريطة الروابط `[S1]`

```
الرئيسية ──← المساعد الذكي
   └──← البحث والخدمات ──← نتائج البحث ──┬──← صفحة الطبيب ──┐
                                          └──← صفحة الفرع  ──┴──← اختيار الموعد
                                                                     │
                                                          مراجعة الطلب
                                                                     │
                                                          بانتظار العيادة
                                                            ├──← حجز مؤكد
                                                            └──← موعد أو عيادة بديلة
```

### 6.7 رحلة الخدمة والتحصيل `[S1]`

**تسجيل الخدمة الفعلية (موظف الاستقبال / الطبيب المفوّض):**
الخدمة المحجوزة ← الخدمة الفعلية ← الطبيب ← وقت التنفيذ ← القيمة المقترحة ← طريقة الدفع ← ملاحظات إدارية ← **إرسال لاعتماد الإدارة**.

> ❗ `[S1]`: «**لا تحفظ المنصة تفاصيل تشخيصية لا تحتاج إليها.**»

**اعتماد القيمة (إدارة العيادة فقط) `[S1]`:**
تعرض: الحجز، الخدمة المحجوزة، الخدمة المنفذة، السعر الأساسي، السعر المقترح، القيمة المحصلة، الخصم، طريقة الدفع، العمولة ← **اعتماد / رفض وإعادة للموظف** + **سجل التعديل**.

### 6.8 رحلة العمولة `[S1]`

```
خدمة منفذة + مبلغ محصل معتمد
        ↓
تطبيق قاعدة العمولة (حسب الأولوية)
        ↓
بند في تسوية مفتوحة
        ↓
إقفال الفترة الشهرية
        ↓
فاتورة مسودة ← صادرة
        ↓
اعتراض (اختياري) ← إشعار تعديل
        ↓
مدفوعة / متأخرة ← سجل السداد
```

## 7. حالات الحجز

### 7.1 الحالات الموحدة المعتمدة `[S2]`

> «✓ حالات موحدة: **جديد، بانتظار التأكيد، مؤكد، حضر، لم يحضر، نُفذت، محصل، ملغي**.»

| الرمز | الحالة (عربي) | English | الوصف |
|---|---|---|---|
| `NEW` | جديد | New | أنشئ الطلب داخليًا قبل الإرسال للعيادة |
| `PENDING_CONFIRMATION` | بانتظار التأكيد | Pending Confirmation | أُرسل للعيادة — ❗ **ليس حجزًا مؤكدًا** |
| `CONFIRMED` | مؤكد | Confirmed | أكدت العيادة الموعد |
| `ATTENDED` | حضر | Attended | سُجل حضور المريض |
| `NO_SHOW` | لم يحضر | No-show | لم يحضر المريض |
| `SERVICE_DONE` | نُفذت | Service Performed | نُفذت الخدمة الفعلية |
| `COLLECTED` | محصل | Collected | حُصّل المبلغ واعتُمد ← **مؤهل للعمولة** |
| `CANCELLED` | ملغي | Cancelled | أُلغي الحجز |

### 7.2 حالات إضافية مذكورة في الوثائق ولم تُدرج في القائمة الموحدة

| الحالة | المصدر | الملاحظة |
|---|---|---|
| **مرفوض** (رفض العيادة مع سبب) | «يؤكد الطلب أو يرفضه مع سبب مسجل» `[S2]`، «إذا رفضت العيادة» `[S1]` | ⚠️ ليست ضمن الحالات الموحدة الثمانية ← **OQ-003** |
| **متأخر** (تجاوز SLA) | «الحجوزات المتأخرة» في لوحة الاستقبال ولوحة زامو `[S1]` | يُقترح أن تكون **علامة (flag)** لا حالة، لأنها تتزامن مع `PENDING_CONFIRMATION` |
| **تأخر** (وصل متأخرًا) | تسجيل الحضور: «حضر / لم يحضر / **تأخر** / أعيدت الجدولة عند الوصول» `[S1]` | تفصيل داخل الحضور |
| **أعيدت الجدولة** | «إعادة جدولة» متاحة `[S1+S2]` | يُقترح أن تكون **انتقالًا** ينشئ حجزًا/نسخة جديدة |

### 7.3 حالات العرض (كيان منفصل) `[S1]`

مسودة ← بانتظار اعتماد إدارة العيادة ← بانتظار مراجعة زامو ← منشور ← منتهٍ ← موقوف.

### 7.4 قواعد الحجز الحاكمة

1. ❗ **إرسال طلب الحجز لا يعني تأكيده.** `[S1+S2]`
2. ❗ الرسالة الصحيحة: **«تم إرسال طلب حجزك إلى العيادة، وسنبلغك فور تأكيد الموعد.»** `[S1]`
3. ❗ **لا تظهر عبارة «تم تأكيد الحجز» قبل رد الاستقبال.** `[S1]`
4. SLA التأكيد: 15–30 دقيقة (مستهدف) / 24 ساعة (حد أقصى) `[S2]`.
5. بعد التأخير: **الوكيل يعاود التواصل ويعرض بدائل** `[S2]`.
6. عند الرفض: **سبب مهني مناسب + خيارات بديلة + إمكانية التحدث مع الوكيل** `[S1]`.
7. **منع التضارب** في التقويم `[S1]`.
8. لا تغير إدارة زامو حجزًا مؤكدًا دون **تسجيل السبب وإبلاغ الأطراف** `[S1]`.

## 8. الوكيل الذكي

### 8.1 المبدأ الحاكم `[S2]`

> لا يقدّم وكيل زامو تشخيصًا أو علاجًا. دوره **إداري**.

### 8.2 ما يستطيع الوكيل فعله `[S1]`

1. سؤال المريض عن الخدمة التي يبحث عنها.
2. معرفة المدينة والحي.
3. معرفة التخصص المطلوب.
4. عرض الأطباء والمواعيد والأسعار.
5. مقارنة الخيارات.
6. إتمام الحجز.
7. إرسال التأكيد والتذكير.
8. تعديل الموعد أو إلغاؤه.
9. الإجابة عن أسئلة المنشأة والخدمة.
10. معرفة مصدر العميل والحملة.
11. **تصعيد المحادثة إلى موظف بشري.**

### 8.3 ما يُمنع على الوكيل

- تشخيص المريض، وصف علاج، اقتراح دواء، تقديم توصية طبية شخصية `[S1+S2]`.
- «لا تستخدم عبارات مثل **أفضل طبيب** إلا وفق **معيار معلن وقابل للإثبات**» `[S1]`.
- «يجب ألا تقدم الصفحة **تشخيصًا أو وعدًا بنتيجة طبية**» `[S1]`.
- عدم وضع أي تشخيص أو نصيحة علاجية داخل رحلة الوكيل `[S1]`.

### 8.4 مكونات واجهة الوكيل `[S1]`

نافذة المحادثة · **تعريف واضح بأن المستخدم يتحدث مع مساعد ذكي** · اختيار اللغة · **زر التحويل إلى موظف** · خطوات تقدم (الخدمة ← الموقع ← التفضيلات ← الخيارات ← الحجز) · بطاقات الأطباء والعيادات داخل المحادثة · زر مقارنة · زر عرض التفاصيل · زر اختيار الموعد · زر تأكيد طلب الحجز · **سياسة الخصوصية والموافقة** · **تنبيه عدم التشخيص** `[S2]`.

### 8.5 إدارة الوكيل من لوحة زامو `[S1]`

تعليمات الوكيل · اللغات · قوالب الأسئلة · **الأدوات المتاحة (Tools)** · **قواعد الطوارئ** · **قواعد التصعيد** · السجلات · **المحادثات الفاشلة** · تقييم الجودة · **إيقاف أداة محددة**.

> هذا يعني معماريًا أن الوكيل يجب أن يُبنى كـ **Tool-calling agent** بأدوات مُعرَّفة قابلة للتفعيل/التعطيل من لوحة الإدارة، لا كنموذج مفتوح.

### 8.6 سيناريو الوكيل المرجعي `[S2]`

> «أريد استشارة جلدية في **الملقا** اليوم» ← استخلاص (تخصص=جلدية، حي=الملقا، تاريخ=اليوم) ← بحث ← عرض خيارات مع سبب الترشيح ← اختيار موعد ← بيانات ضرورية فقط ← إرسال الطلب ← **بانتظار تأكيد العيادة**.

- صفحة «حقوق ومسؤوليات المريض».

### 10.5 التنبيه النظامي `[S2]`

**⛔ تنبيه هندسي:** المستندات **لا تسمّي** نظامًا قانونيًا محددًا. لذلك لن تفترض هذه الوثيقة الامتثال لأي إطار بعينه، وسنبني ضوابط تقنية عامة (تشفير، تقليل بيانات، احتفاظ، حذف، تدقيق) تدعم أي إطار يقرره المختص القانوني. ← **OQ-004**.

7. ✓ **تصميم الواجهات للجوال أولًا (Mobile First)** `[S1]`.

### 12.7 قواعد التصميم المعتمدة رسميًا `[S1]`

1. جعل الوكيل الذكي هو المسار الأساسي.
2. توفير البحث اليدوي كمسار بديل.
3. تقليل البيانات المطلوبة من المريض.
4. **توضيح سبب ترشيح كل طبيب.**
5. عرض الفرع والحي والسعر والموعد معًا.
6. **عدم وصف الحجز بأنه مؤكد قبل موافقة الاستقبال.**
7. **فصل الموافقة على رسائل الحجز عن الموافقة التسويقية.**
8. **إبراز الحجوزات المتأخرة داخل لوحة الاستقبال.**
9. توفير أزرار سريعة للتأكيد أو اقتراح بديل أو الرفض.
10. تصميم الواجهات للجوال أولًا.
11. عدم وضع أي تشخيص أو نصيحة علاجية داخل رحلة الوكيل.
